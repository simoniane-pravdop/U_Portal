# Управлінський портал

Локальна робоча версія порталу для стратегічних цілей, управлінських циклів, підциклів і завдань.

Порядок внесення змін, перевірок і розміщення зафіксовано в
[`DEVELOPMENT_WORKFLOW.md`](./DEVELOPMENT_WORKFLOW.md).

Тестова версія: [pravdop-management-portal.simonian-e-be8.workers.dev](https://pravdop-management-portal.simonian-e-be8.workers.dev/).
Кожна перевірена зміна в гілці `main` автоматично розгортається через GitHub Actions.

## Що реалізовано

- дерево `S → P → завдання` або `S → P → P.x → завдання` зі стабільними кодами;
- окремі контури: дерево для структури й паспортів, `Моя робота` для виконання та звітування;
- редагування, додавання нижчого рівня й контрольоване видалення безпосередньо в дереві;
- компактний режим дерева лише за кодами, меню дій під трьома крапками та мобільне перемикання `Дерево / Картка`;
- адаптивна щільність для невеликого ноутбука, планшета й телефона з нижньою мобільною навігацією;
- відповідальні, виконавці, особи, які приймають результат, строки та повноваження;
- паралельні й послідовні залежності та режим старту після звільнення ресурсу;
- блокери, запити управлінських рішень, приймання результату й докази;
- координаційні знімки на рівні підциклу без поля проміжного результату;
- робоча картка задачі зі станом, прогресом, прогнозом, звітом, наступною дією та історією;
- автоматичне підняття прогресу й стану виконання із задач до підциклу, циклу та цілі;
- автоматичний розрахунок прогресу верхніх рівнів без перенесення ризику окремого завдання на все дерево;
- відновлення незбережених чернеток після оновлення сторінки;
- багатокористувацьке автооновлення, повтор збереження після зміни іншого користувача та блокування одночасного редагування одного паспорта;
- панель погоджень і внутрішні питання/коментарі з окремим реєстром незакритих питань у координації;
- фільтри дерева, дашборда й координації, а також пошук і сортування у «Моїй роботі»;
- компактний режим до 1366 px для 13-дюймових ноутбуків із вертикальним розміщенням робочих блоків і читабельнішими підписами;
- прив’язування наявної задачі Asana або створення нової безпосередньо з робочої картки з автоматичним додаванням до контрольних місць;
- стабільні вебпосилання на кожну ціль, цикл, підцикл і завдання з підтримкою навігації браузера назад/уперед;
- єдиний керівницький дашборд із результатами, блокерами, рішеннями, строками й навантаженням;
- вхід за визначеною корпоративною адресою та паролем, захищені сесії й обмеження невдалих спроб;
- власник порталу та адміністратор із розділеними повноваженнями;
- створення доступу, ролей, вимкнення користувачів і генерація нових паролів у налаштуваннях;
- зберігання структурованого стану в D1; локальна підтримка файлів у R2, який у безкоштовній онлайн-версії поки вимкнений;
- персональний Asana OAuth із зареєстрованим застосунком; можливість Google OAuth залишена для наступного етапу;
- правила синхронізації окремо для кожного поля;
- Telegram-бот із захищеним webhook, одноразовою персональною прив’язкою, командою `/my`, тестовим повідомленням і сповіщеннями про блокери, рішення та приймання;
- модель повторюваних циклів, вимкнена до появи першого реального випадку.

## Локальний запуск

1. Скопіювати `.env.example` у `.env`, додати випадковий 256-бітний секрет захисту паролів і похідні PBKDF2-записи двох початкових паролів. Відкриті паролі в `.env` не зберігаються.
2. Запустити `npm run dev`.
3. Відкрити адресу, яку покаже локальний сервер.

Для Asana потрібен зареєстрований OAuth-застосунок із дозволами `tasks:read`, `tasks:write`, `projects:read`, `users:read` та точною адресою повернення `/api/asana/callback`. Для Telegram потрібно створити бота через `@BotFather`, додати `TELEGRAM_BOT_TOKEN` і випадковий `TELEGRAM_WEBHOOK_SECRET`, а потім натиснути «Увімкнути webhook» у налаштуваннях порталу.

Початковий стан містить лише власника порталу Володимира Гурлова та адміністратора Едгара Сімоняна; тестових цілей, циклів, завдань і користувачів немає. Жодна операція в Asana не виконується автоматично: створення або передання змін запускає користувач окремою кнопкою.

## Контроль перед розміщенням

- перевірити вхід обох початкових адміністраторів і створення доступу для нового користувача;
- зареєструвати Google OAuth і Asana OAuth із постійною адресою повернення;
- додати 32-байтовий ключ шифрування токенів;
- визначити хостинг і політику резервного копіювання;
- увімкнути автоматичні повідомлення Asana лише після появи публічної HTTPS-адреси;
- перевірити доступ до конфіденційних циклів і файлів на реальних ролях.
