# Порядок розробки та розміщення

Цей порядок є обов’язковим для кожної зміни Управлінського порталу.

## Основний цикл

```text
Локальний проєкт
  → локальна перевірка
  → викладення в GitHub
  → автоматичне оновлення Cloudflare
  → онлайн-перевірка
  → готово або повернення до локального проєкту
```

Зміни не вносяться вручну безпосередньо у розгорнутий застосунок Cloudflare.
Код у GitHub є єдиним джерелом версії, що розміщується онлайн.

## 1. Локальний проєкт

1. Отримати актуальну версію гілки `main`.
2. Внести зміни лише в локальній копії проєкту.
3. Запустити портал командою `npm run dev`.
4. Перевірити змінений сценарій на тестових даних.
5. Не додавати ключі, паролі, токени або вміст `.env` до GitHub.

## 2. Локальна перевірка

Перед кожним викладенням необхідно:

1. Запустити `npm test`.
2. Запустити `npm run lint`.
3. Перевірити сторінки на широкому екрані, 13-дюймовому ноутбуці та мобільній ширині.
4. Перевірити створення, редагування, видалення й відкриття цілей, циклів, підциклів і завдань.
5. Перевірити вхід, завершення сесії, ролі та керування доступом до порталу.
6. Перевірити підняття стану із завдання до підциклу, циклу та цілі.
7. Переконатися, що в змінах немає конфіденційних даних і сторонніх файлів.

Якщо хоча б одна перевірка не пройдена, зміна не передається в GitHub.

## 3. Викладення в GitHub

1. Переглянути перелік змінених файлів.
2. Створити окремий зрозумілий коміт.
3. Передати коміт у репозиторій `simoniane-pravdop/U_Portal`.
4. Перевірити, що локальна гілка і GitHub містять однаковий коміт.

Потрапляння перевіреного коміту в `main` є дозволом для автоматичного
розгортання цієї версії в тестовому середовищі Cloudflare.

## 4. Оновлення Cloudflare

1. GitHub Actions запускається автоматично після передання коміту в `main`.
2. Сценарій встановлює залежності, перевіряє код, збирає застосунок і запускає тести.
3. Лише після успішних перевірок сценарій розгортає Worker у Cloudflare з D1-базою `u-portal-db`.
4. Ключ розгортання зберігається як зашифрований секрет GitHub і має лише права `Workers Scripts: Edit` та `D1: Edit` для одного облікового запису Cloudflare.
5. Ідентифікатори облікового запису та D1 зберігаються як відкриті службові змінні GitHub; конфіденційних значень у коді немає.
6. Робочі секрети порталу й OAuth-ключі зберігаються лише в налаштуваннях Cloudflare.
7. Для безкоштовного випробування R2 не підключається, тому завантаження файлів
   онлайн тимчасово недоступне.
8. Якщо складання або розгортання завершилося помилкою, попередня працездатна
   версія вважається чинною, а виправлення починається локально.

## 5. Онлайн-перевірка

Після кожного розгортання на адресі `workers.dev` потрібно перевірити:

1. відкриття порталу та авторизацію;
2. дерево цілей, циклів і завдань та робочі картки;
3. збереження зміни після оновлення сторінки;
4. персональні права користувачів;
5. створення звіту, блокера та запиту рішення;
6. коректність дашборда і підняття станів;
7. відсутність помилок у журналі Cloudflare;
8. показники використання Workers і D1 до та після перевірки.

Перевірка інтеграції з Asana виконується окремо й лише тестовою дією, яку
користувач свідомо запускає у порталі.

## Контроль безкоштовного тарифу

- Workers і D1 залишаються на безкоштовному тарифі; платний Workers-план не
  підключається без окремого рішення власника.
- R2 не активується на першому етапі, оскільки це тариф із можливістю оплати за
  перевищення використання.
- Перед і після онлайн-перевірки переглядаються лічильники Workers і D1.
- Досягнення безкоштовного ліміту означає тимчасову зупинку операцій, а не
  автоматичний перехід на платний тариф.
- Будь-яке підключення платного продукту, платіжного способу або тарифу потребує
  окремого підтвердження власника.

## Умова завершення зміни

Зміна має стан `готово` лише тоді, коли одночасно виконано всі умови:

- локальні перевірки пройдено;
- коміт присутній у GitHub;
- Cloudflare успішно розгорнув саме цей коміт;
- онлайн-перевірка пройдена;
- використання залишається в межах безкоштовного тарифу.

Якщо онлайн-перевірка виявила помилку, цикл починається знову з локального
проєкту. Виправлення не робиться безпосередньо в Cloudflare.
