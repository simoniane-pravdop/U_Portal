# Незалежна VPS-копія порталу

Адреса копії: https://up.automatizer.online. Оригінальна Cloudflare-версія працює окремо. Зміни користувачів після знімка даних між версіями не синхронізуються. Гілка `deployment/vps-copy` не запускає автоматичне викладення Cloudflare з `main`.

## Ізоляція

- SSH: наявний псевдонім `juscript-vps`.
- Каталог: `/opt/u-portal`; випуски у `releases/<commit>`, посилання `current`.
- Окрема служба Docker Compose `u-portal-copy`, внутрішній порт `127.0.0.1:3101`.
- Дані: `/opt/u-portal/shared/data/portal.sqlite`. Вони не входять до образу чи Git.
- Секрети: `/opt/u-portal/shared/portal.env`, права `600`. Ніколи не виводити його в журнали.
- Віртуальний хост Nginx лише `up.automatizer.online`. Наявні файли Juscriptum не змінюються.
- DNS: додано лише `A up → 167.86.92.99`, без заміни зони.

Копія містить картки, звіти, історію та чинні облікові записи зі знімка. Активні сеанси, особисті підключення Asana, Telegram і черга вихідних повідомлень не копіюються. OAuth-ключі, бот і планові зовнішні дії вимкнені; звичайні збережені посилання залишаються. Вхід Google не налаштований; використовується чинний вхід поштою та паролем. Файлове сховище R2 не встановлено, як і в поточному безкоштовному середовищі.

## Порядок змін

Локальна зміна → перевірки → окремий випуск у GitHub → складання VPS-образу → оновлення тільки служби порталу → перевірка копії та `https://www.juscriptum.online/api/health`.

Перевірки: `npm test`, `npm run lint`, `npx tsc --noEmit`, `npm run build:vps`. Нормальна команда `npm run build` і Cloudflare залишаються незмінними. VPS потребує Node.js ≥22.13 з `node:sqlite`.

На VPS перед оновленням зберегти резервну копію БД. Скрипт можна виконати через стандартний ввід без встановлення його у контейнер:

```sh
cd /opt/u-portal/current
PORTAL_IMAGE_TAG=<commit> docker compose -f ops/vps/compose.yml exec -T portal node --input-type=module < ops/vps/backup.mjs
```

Резервні БД лежать у `/opt/u-portal/shared/data/backups`. Початковий знімок і секрети додатково збережені у захищеному `/opt/u-portal/backups`. Резервне копіювання перед оновленням ручне; новий плановий розклад не створювався.

## Відновлення

Не підміняти живу БД без зупинки **тільки** служби порталу та окремого резервування поточного стану. Для відкату коду обрати попередній образ і випуск, оновити `current`, виконати Compose з відповідним `PORTAL_IMAGE_TAG`. Не знижувати версію схеми без перевірки сумісності. Для відновлення БД після зупинки служби замінити її перевіреною резервною копією, прибрати лише відповідні WAL/SHM-файли збереженої старої БД, перевірити власника `1000:1000`, запустити портал та перевірити вхід/картки. Ніколи не використовувати загальне очищення Docker або перезапуск VPS.

Сертифікат отримується через Certbot `certonly --webroot`, окремий каталог `/opt/u-portal/shared/acme`. Наявний механізм поновлення Certbot використовується без зміни сертифікатів інших сайтів. `renew-certificate.sh` встановлюється в `/etc/letsencrypt/renewal-hooks/deploy/u-portal-reload`; він перевіряє конфігурацію та перечитує її лише після поновлення сертифіката порталу.

У гілці копії React/React DOM/RSC оновлені до 19.2.8, а обробник розмірів зображень — до 2.0.3: усунено відомі попередження цих робочих компонентів. Загальне оновлення інструментів розробки до наступних версій не виконувалося; їхні попередження `npm audit` потребують окремого обслуговування. Це не повний аудит безпеки порталу.
